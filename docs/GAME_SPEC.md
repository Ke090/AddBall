# AddBall ゲーム仕様

この文書を、ゲームの挙動と一般公開要件に関する唯一の正とします。

## コンセプトと不変条件

AddBallは、固定された論理座標10×10の正方形内で遊ぶ物理ゲームです。ゲーム開始時の玉の数は1〜100から選択でき、選択した数だけ面積1の玉を生成します。すべての玉は中央に面積を表示し、プレイ中の総面積は開始時の玉の数と等しく保たれます。

ゲーム上の値は半径ではなく面積です。面積 `A` の論理半径は `Math.sqrt(A / Math.PI)` とし、物理座標を画面ピクセルへ依存させてはいけません。

## 移動と操作

- 玉へランダムな力は加えません。玉は投球、端末の傾き、衝突によって動き、わずかな摩擦と最高速度制限によって安定させます。
- 摩擦、重力、ポインター入力がない間は、玉同士の衝突、合体、分裂で系の運動量を保存します。摩擦と重力が0の場合、衝突計算の数値誤差によって運動エネルギーを増加させません。
- Pointer Eventsで玉を選択、ドラッグ、リリースできます。リリース時は直前のドラッグ速度を引き継ぎ、タッチとマウスのどちらでも投げられます。操作中のスクロール、overscroll、pull-to-refresh、テキスト選択の誤作動を防ぎます。
- 玉をダブルタップまたはダブルクリックすると、分裂確率にかかわらず分裂します。面積1は分裂しません。移動距離の閾値を設け、ドラッグをダブルタップとして扱いません。
- 対応するスマートフォンでは、端末の傾きを重力として使用します。左右の傾きは左右へ、手前・奥への傾きは下・上へ対応させます。STARTまたは「傾きを再調整」を実行した時点の姿勢を中立位置とします。入力にはdead zone、clamp、low-pass smoothingを適用し、可能な限り画面方向の変化も考慮します。
- センサー権限は、ユーザー操作を受けてから要求します。拒否、利用不可、未対応の場合は傾き操作だけを無効にし、ゲームは継続します。

## 衝突ルール

玉同士が接触すると、衝突速度によらず設定された確率で2つの玉を合体させます。合体しなかった場合は弾性衝突します。面積は加算し、位置は面積による加重平均、速度は可能な限り運動量を保存する値とします。新しい半径は合計面積から再計算します。

壁との衝突は反発係数1の弾性衝突とします。摩擦と重力が0なら、壁で反射しても玉の速さを維持します。分裂可能な玉は衝突速度によらず設定された確率で `floor(N / 2)` と `ceil(N / 2)` に分裂し、面積1は分裂しません。分裂後の各玉は分裂前と同じ速度ベクトルを引き継ぎ、分裂によって加速しません。分裂後3秒間はほかの玉と合体できません。`SPLIT_COOLDOWN_MS` により、分裂直後の連続分裂も防ぎます。

衝突コールバックでは測定とアクション登録だけを行い、物理更新後にワールドを変更します。予約済みIDの集合を使い、同じ玉が1回の物理ステップ内で複数の合体・分裂に参加することや、削除済みbodyが再利用されることを防ぎます。

## 表示とフィードバック

- 独自の高DPI対応Canvas rendererで、フィールド、玉、玉の大きさに応じた中央の面積値を描画します。
- 見た目はミニマル、清潔、現代的、モバイル優先、ゲームプレイ優先とします。短い合体pulse、分裂shockwave、控えめな衝突feedbackを表示しますが、演出によってゲームを止めません。
- Web Audio APIで通常衝突、合体、分裂の効果音を生成します。ユーザー操作前に音声を開始せず、音声をOFFにできるようにします。
- 縦画面と横画面でsafe areaを考慮します。画面サイズの変更によって論理物理空間を変えたり、玉をフィールド外へ取り残したりしてはいけません。

## スタート画面とメニュー

初期画面には「30」「玉をぶつけて、大きくする。」「壁に当たると、確率で割れる。」およびSTARTボタンを表示します。START操作を受けて音声を開始し、任意のセンサー権限を要求します。ゲーム内メニューには「はじめから」「傾き ON/OFF」「傾きを再調整」「サウンド ON/OFF」に加え、初期の面積1の玉の数（1〜100）、摩擦力、重力、合体確率、分裂確率のスライダーを用意します。初期の玉の数を変更すると、直ちにゲームを再スタートします。

## 設定とパフォーマンス

フィールドサイズ、初期個数の範囲、総面積、反発係数、摩擦、最高速度、傾き重力・dead zone・smoothing、合体・分裂確率、分裂cooldownを含むすべてのバランス値を `src/game/config.ts` に集約します。スライダーの値は端末内へ保存します。

現行スマートフォンで60fpsを目標とします。`requestAnimationFrame` を使用し、物理演算と描画を分離し、大きなframe deltaを制限し、バックグラウンド時は安全に停止します。任意表示のデバッグHUDを除き、ループ中の継続的なDOM更新を避けます。

## デバッグモード

URLへ `?debug=1` を付けた場合のみ、FPS、玉の数、総面積、重力、合体・分裂確率を表示します。総面積が開始時の玉の数と異なれば明確に警告し、通常アクセスではデバッグHUDを表示しません。

## PWAとプライバシー

Web App Manifest、独自アイコン、theme/background color、standalone表示、start URL、バージョン管理されたService Workerのapplication shell cacheを提供します。新しいService Workerは古いcacheを削除します。アプリはクライアント側のみで動作し、静的ホスティングとHTTPSで公開できます。

アカウント、広告、アクセス解析、トラッキング、シークレット、不要な外部通信を使用しません。センサー値を端末外へ送信しません。依存packageは実行時CDNから取得せずbundleします。localStorageへ保存できるのはサウンド、傾き、初期の玉の数、摩擦力、重力、合体確率、分裂確率の設定だけです。

## 受け入れテスト

unit testでは、合体と分裂の面積保存、面積1の分裂禁止、初期個数1・7・30・100で各玉が面積1かつ総面積が初期個数と一致すること、同一ステップの衝突競合防止、分裂時の速度継承、分裂直後の合体禁止、分裂確率0での直接分裂、摩擦・重力0での壁反射時の速度維持、および無外力時の運動量と運動エネルギー保存を検証します。可能な場合はbrowser smoke testで、読み込み、START、Canvas、再スタート、未処理のJavaScriptエラーがないことを検証します。
